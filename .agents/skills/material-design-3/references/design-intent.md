# Design intent before Material styling

Use this reference before substantial new UI work or an M3 Expressive redesign. Material components and tokens do not decide product intent for you.

## Derive a small design brief first

Before choosing color, shape, motion, or component variants, identify:

1. **Primary user task** — what must be easy, fast, safe, or discoverable?
2. **Information hierarchy** — what is primary, supporting, optional, or dangerous?
3. **Density** — calm/content-led, standard application density, or dense operational tooling?
4. **Personality** — restrained, warm, technical, playful, editorial, premium, etc.
5. **Brand constraints** — source colors, typeface, iconography, product-specific shapes, and non-negotiable conventions.
6. **Input/accessibility context** — touch, mouse/keyboard, rotary, screen reader, text scaling, localization.
7. **Adaptive needs** — what should become a second pane, rail/drawer, supporting region, or bounded content area when space grows?
8. **Expressive intensity** — none, subtle, focused, or hero-level.

Keep this brief short. It is a decision aid, not a design manifesto.

## Expressive calibration

Material 3 Expressive should solve a hierarchy or usability problem. Choose the smallest useful set of levers: color contrast, size contrast, shape contrast, containment, and motion.

Repeated utility actions should stay familiar and efficient. Reserve stronger motion, larger scale, or unusual shape for moments that benefit from emphasis.

## Agent output rule

When the user asks to create or redesign a meaningful screen, be able to explain internally why the primary action is primary, why the navigation form matches the information architecture, where expressive treatment is intentionally concentrated, which existing project tokens/components are being reused, and what changes at narrow and wide layouts.

Do not add a visible “design brief” to the product unless the user asks for one.

## Existing products

If the repository already has a coherent design system, infer intent from its existing screens, tokens, components, and product conventions. Material adoption is not permission to erase brand identity or replace established interaction patterns.
